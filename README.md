# TradingForBeginner

주식을 처음 시작하는 입문자를 위한 사이트를 바이브코딩을 통해 제작

**배포 주소**: https://tradingforbeginner.chamch134.workers.dev/

## 기술 스택

- [Astro](https://astro.build/) (정적 사이트 생성)
- Cloudflare Workers (정적 자산 배포, GitHub 연동 자동 배포)

## 진행 방식

한 번에 모든 기능을 만들지 않고, 아래 순서로 단계별로 콘텐츠를 추가합니다.

1. ✅ 기본 사이트 골격 — 홈, 헤더/푸터, `/concepts` `/domestic` `/us` 자리표시자 페이지
2. ✅ 기본 개념 콘텐츠 (`/concepts`) — 주식 기초 용어 100개 + 실전 보충 용어 8개(총 108개)를
   "용어가 설명하는 대상"을 기준으로 13개 주제 영역(소유 구조, 실전 매매, 자금조달, 상장 절차,
   주주환원, 공시, 투자자 유형, 매매 전략, 재무제표, ETF, 기술적 지표, 매매 심리 등)으로 정리해
   페이지에 반영 완료
3. 🔄 국내 주식 현황·분석 (`/domestic`) — 진행 중
   - ✅ 최근 1개월 누적 거래량 TOP10 (개별 종목 / ETF·ETN 포함 2종)
   - ✅ 종목 상세 페이지 (`/domestic/[종목코드]`) — 일봉 차트, 한 주당 매수/매도 가격, 최근 1주일 시가
   - ⬜ 코스피·코스닥 지수 현황, 20·60일 이동평균선, 시가총액 등 종목 기본정보
4. ⬜ 미국 주식 현황·분석 (`/us`)

## 개발

```bash
npm install
npm run dev       # http://localhost:4321 개발 서버
npm run build     # dist/ 에 정적 파일 빌드
npm run preview   # 빌드 결과 로컬 미리보기
```

### 시세 데이터 갱신

`/domestic`의 거래량 TOP10은 **커밋된 JSON 파일**을 읽습니다. 빌드할 때 외부 API를
호출하지 않으므로, KRX가 응답하지 않아도 배포는 절대 실패하지 않습니다.
숫자를 최신으로 바꾸려면 로컬에서 아래 명령을 실행한 뒤 커밋·푸시하면 됩니다.

```bash
npm run collect:domestic   # 약 90초 (Node 22.18+ 또는 24+ 필요)
```

기업의 재무 숫자(PER·PBR용)는 거래소가 아니라 전자공시에 있어 별도 스크립트로 받습니다.

```bash
npm run collect:fundamentals   # 약 10초 (최초 1회는 고유번호 20MB 내려받기 포함)
```

#### 최초 1회 설정: KRX 인증키

1. [openapi.krx.co.kr](https://openapi.krx.co.kr) 회원가입 후 **인증키 신청** (관리자 승인 필요)
2. 인증키만으로는 호출되지 않습니다. 아래 4개 서비스에 각각 **API 활용 신청**을 넣고 승인받으세요.
   승인 전에는 `401 Unauthorized API Call`이 돌아옵니다.
   - 유가증권 일별매매정보 · 코스닥 일별매매정보 · ETF 일별매매정보 · ETN 일별매매정보
3. 저장소 루트에 `.env` 파일을 만들고 키를 넣습니다 (이 파일은 `.gitignore`에 등록되어 있어
   커밋되지 않습니다):

   ```
   KRX_AUTH_KEY=발급받은키
   ```

#### 최초 1회 설정: DART 인증키

PER·PBR을 계산하려면 회사의 **당기순이익**과 **자본총계**가 필요한데, KRX OPEN API에는
이 두 값이 없습니다. 거래소는 시세를 주는 곳이지 재무제표를 주는 곳이 아니기 때문입니다.
그래서 금융감독원 전자공시(DART)의 공식 OpenAPI에서 받아옵니다. 감사받은 정기보고서가
원천이라 출처가 분명합니다.

1. [opendart.fss.or.kr](https://opendart.fss.or.kr) 회원가입 후 **인증키 신청** —
   이메일 인증이면 끝이고, KRX와 달리 서비스별 활용 신청 절차가 없습니다
2. 같은 `.env` 파일에 한 줄 추가합니다:

   ```
   DART_API_KEY=발급받은키
   ```

키가 없어도 사이트는 정상 빌드됩니다. `fundamentals.json`이 비어 있으면 PER·PBR 카드가
접히고 "아직 재무 자료를 수집하지 않았습니다"라는 안내만 나옵니다.

#### 동작 방식

수집은 **두 단계**로 나뉩니다. 순위와 지표가 필요로 하는 기간이 다르기 때문입니다.

| 단계 | 기간 | 대상 | 쓰임새 |
|---|---|---|---|
| 1단계 | 최근 1개월 (약 22영업일) | 전 종목 (약 4,300개) | 누적 거래량 TOP10, 차트 |
| 2단계 | 그 이전 5개월 (약 100영업일) | 1단계에서 뽑힌 20종목만 | 60일선·MACD 등 기술적 지표 |

순위는 "최근 1개월 거래량"이라는 정의를 지켜야 하므로 1단계 창에서만 집계하고, 시세만
6개월로 늘립니다. 2단계는 순위가 정해진 뒤에야 어떤 종목이 필요한지 알 수 있어 순서를
바꿀 수 없습니다. KRX Open API에는 "종목 하나의 기간 시세"를 주는 창구가 없고 날짜별 전
종목만 있어서, 하루씩 받아 필요한 종목을 골라내는 수밖에 없습니다. 대신 2단계에서는 어떤
엔드포인트가 필요한지 이미 알고 있으므로(TOP10에 코스닥 종목이 없으면 코스닥은 아예 호출하지
않습니다) 그만큼 요청 수를 줄입니다.

- 수집 결과는 파일 **두 개**로 저장됩니다. **둘 다 생성물이므로 손으로 수정하지 마세요.**
  - [`src/data/domestic/top10.json`](./src/data/domestic/top10.json) — 순위표
  - [`src/data/domestic/daily.json`](./src/data/domestic/daily.json) — 상세 페이지용 일별 시세
    (순위표에 오른 20종목 × 6개월, 약 550KB)
- 두 파일은 **반드시 같은 실행에서 함께 갱신**됩니다. 한쪽만 새것이면 순위표에는 있는데
  상세 페이지가 없는 종목이 생겨 링크가 깨지기 때문입니다.
- `daily.json`의 `window`는 순위·차트에 쓰는 최근 1개월, `history`는 지표 계산에 쓰는
  6개월 전체입니다. `series[].days`에는 6개월치가 통째로 들어 있으므로, 차트를 그릴 때는
  `chartBars()`로 최근 1개월만 잘라 씁니다.
- 원본 응답은 `.cache/`에 단계별로 캐시됩니다(git 무시). 1단계는
  `krx-daily-v2-{시작일}-{종료일}.json`, 2단계는 `krx-hist-v2-{시작일}-{종료일}.json`이며
  2단계 캐시에는 **어떤 종목을 담았는지**도 함께 적혀, 순위가 바뀌어 새 종목이 들어오면
  자동으로 다시 받습니다. 파일명의 `v2`는 캐시 스키마 버전이라 수집 항목이 바뀌면 올려서
  옛 캐시를 자연히 버립니다.
- 수집이 실패하면 **기존 JSON 두 개를 모두 건드리지 않고** 종료 코드 1로 끝납니다.
  사이트는 마지막으로 성공한 데이터를 계속 보여줍니다.
- KRX는 당일 자료를 약 1영업일 뒤에 공개합니다. 그래서 스크립트가 오늘부터 거꾸로 훑어
  **실제로 데이터가 있는 가장 최근 영업일**을 기준일로 잡습니다.

## Cloudflare 배포

이 프로젝트는 정적 사이트(Astro `output: "static"`, 기본값)입니다. 저장소 루트의
[`wrangler.jsonc`](./wrangler.jsonc)가 `dist/` 폴더를 정적 자산(assets)으로만 배포하도록
지정하고 있어서, Cloudflare Workers 런타임(Miniflare/workerd)이나 SSR 어댑터가 전혀 필요 없습니다.

### 방법 1: Cloudflare 대시보드에서 Git 연동 (권장)

1. Cloudflare 대시보드 → **Workers & Pages** → **Create application** → **Import a repository**
2. 이 저장소 선택
3. 빌드 설정
   - Build command: `npm run build`
   - Deploy command: `npx wrangler deploy`
4. 배포 후 main 브랜치에 푸시하면 자동으로 재배포됩니다.

> 대시보드가 "Deploy command"를 요구하는 최신 Workers Git 연동 방식을 쓰는 경우, 저장소에
> `wrangler.jsonc`가 없으면 Cloudflare가 매 빌드마다 `astro add cloudflare`로 SSR 어댑터를
> 자동 설치하려고 시도합니다. 이때 자동 생성되는 `compatibility_date`가 항상 "오늘 날짜"로
> 잡히는데, 빌드 서버에 내장된 workerd 런타임 바이너리가 그 날짜를 아직 지원하지 않으면
> `MiniflareCoreError [ERR_RUNTIME_FAILURE]` 오류로 배포가 실패합니다. 저장소에 `wrangler.jsonc`를
> 미리 커밋해두면 이 자동 설정 자체가 실행되지 않아 문제가 재발하지 않습니다.

### 방법 2: Wrangler CLI로 수동 배포

```bash
npm run build
npx wrangler deploy
```

> 현재는 정적 자산만 배포하지만, 이후 실시간 시세·로그인 등 서버 기능이 필요해지면
> Astro의 [Cloudflare adapter](https://docs.astro.build/en/guides/integrations-guide/cloudflare/)를 추가해
> SSR/Workers 기반으로 전환할 수 있습니다.

### 국내 주식(`/domestic`) — 1개월 누적 거래량 TOP10

- 코스피·코스닥 **전 종목 4,294개**(주식 2,764 / ETF 1,160 / ETN 370)의 일별 시세를 모아
  최근 1개월 누적 거래량 상위 10종목을 표로 정리
- 표를 2개로 분리: 메인은 **개별 기업 주식만**, 접이식 보조 표는 **ETF·ETN 포함**
  - 거래량은 "몇 주가 거래됐나"를 세는 지표라 주가가 낮을수록 유리하다. 96원짜리
    `KODEX 200선물인버스2X`가 2,060억 주로 삼성전자(6.3억 주)의 약 327배를 기록하는데,
    ETF를 함께 줄 세우면 TOP10에 개별 기업이 **한 종목도 남지 않아** 초보자에게 오해를 준다
  - 같은 이유로 거래량 옆에 **거래대금 열**을 함께 배치 (신일전자 1,894억 vs SK이터닉스 9.8조)

**데이터 소스 선정 과정** — 후보를 실제로 호출해 검증한 결과:

| 후보 | 결과 |
|---|---|
| 페이지에서 브라우저 직접 호출 | ❌ 네이버가 `Origin` 헤더가 붙으면 **403** (CORS 차단) |
| `data.krx.co.kr` JSON 엔드포인트 | ❌ 모든 요청에 **`LOGOUT`** 응답 (회원제로 전환됨) |
| 로컬 수집 → JSON 커밋 → 빌드타임 import | ✅ 채택 |

- 수집기 [`scripts/collect-domestic.ts`](./scripts/collect-domestic.ts) 추가 (`npm run collect:domestic`).
  의존성 없이 Node 내장 `fetch`만 사용, 동시성 6 + 지수 백오프 3회 재시도
- 네이버 `siseJson` 응답은 헤더 행이 홑따옴표라 `JSON.parse`가 그대로는 실패한다.
  `text.replace(/'/g, '"')`로 치환 후 파싱 (전 종목 대상으로 검증, 실패 0건)
- 종목코드에 영문자가 섞인 게 373개(`0193T0` 등) 있어 문자열로만 취급
- 거래대금은 일별 `종가 × 거래량` 합계로 계산한 **추정치**(실제 체결가 기준값은 무료 소스에
  없음). 페이지와 이 문서 양쪽에 추정임을 명시
- 표 스타일(`.rank-table`, `.table-wrap`)을 새로 추가. 모바일에서는 표만 가로 스크롤되고
  페이지 본문은 밀리지 않는다. 접기는 자바스크립트 없이 네이티브 `<details>` 사용

### 국내 주식 — 데이터 소스를 KRX OPEN API로 전환

네이버 비공식 API로 시작했지만, [openapi.krx.co.kr](https://openapi.krx.co.kr) 인증키를 발급받고
4개 서비스(유가증권·코스닥·ETF·ETN 일별매매정보) 활용 승인을 받아 **공식 거래소 데이터로 교체**.

- **거래대금이 추정치에서 실제값으로** — 기존에는 일별 `종가 × 거래량`으로 근사했다.
  같은 기간 삼성전자로 대조하니 추정치 오차가 −0.64%였고, 이제 `ACC_TRDVAL`(거래소 공시
  집계값)을 그대로 쓴다. 페이지의 "추정" 문구도 제거
- **요청 수 4,294건 → 128건** — 네이버는 종목별로 한 번씩 불러야 했지만 KRX는 하루치 전 종목이
  한 응답에 담긴다 (32일 × 4개 서비스)
- **교차 검증** — 같은 기간 삼성전자 누적 거래량이 네이버 713,402,121주 / KRX 713,402,121주로
  **정확히 일치**. 영업일 23일과 공휴일(20260717)도 두 소스가 동일

전환 중 겪은 함정 세 가지:

- **ETF·ETN 응답에는 `MKT_NM` 필드가 없다.** 국내 ETF·ETN은 전부 유가증권시장 상장이므로
  `KOSPI`로 채운다
- **ETF·ETN 엔드포인트는 휴장일에도 행을 돌려준다** (거래량 0 / 종가 빈 값인 껍데기).
  이걸로 영업일을 세면 주말까지 포함돼 한 달이 32영업일이 된다. 영업일 판정은 주식
  엔드포인트로만 하고, 껍데기 행은 건너뛴다. 재발 방지로 영업일 25일 초과 시 실패하는
  검증을 넣었다
- **KRX는 당일 자료를 약 1영업일 뒤에 공개한다.** 오늘 날짜를 기준으로 잡으면 빈 응답이
  오므로, 거꾸로 훑어 실제 데이터가 있는 최근 영업일을 찾는다
- 인증키 발급만으로는 호출되지 않고 **서비스별 활용 신청·승인**이 따로 필요하다.
  이때 `401 Unauthorized API Call`이 오는데, 키 자체가 틀렸을 때의
  `401 Unauthorized Key`와 메시지가 달라 구분할 수 있다

### 국내 주식 — 종목 상세 페이지 (`/domestic/[종목코드]`)

순위표의 종목명을 누르면 그 종목만 따로 보는 페이지로 들어갑니다. 순위표에 오른 20종목
(개별 10 + ETF·ETN 10)에 대해 빌드 때 정적 페이지가 생성됩니다.

**일봉 차트** — 네이버 증권·토스증권 등 실제 증권사 차트를 참고했습니다. 국내 주식 입문
자료들이 공통으로 꼽는 "차트 3요소(캔들·이동평균선·거래량)"가 그대로 증권사 기본 화면이라,
단순 꺾은선 대신 그 구성을 따랐습니다. 여기서 익힌 그림이 실제 증권사 앱에서 그대로 통하게
하려는 의도입니다.

- 캔들은 국내 관행대로 **오르면 빨강(양봉), 내리면 파랑(음봉)** — 미국과 반대라는 설명을 범례에 첨부
- **5일·20일 이동평균선**을 그립니다 (아래 "기술적 신호" 항목에서 6개월치를 모으게 되면서
  추가했습니다). 60일선까지 얹으면 캔들 22개짜리 화면이 선으로 뒤덮여, 신호 패널에서
  숫자로만 보여줍니다
- 사이트 전체가 자바스크립트 0줄이라 **차트 라이브러리를 쓰지 않고 빌드 타임에 SVG를 직접**
  그립니다. 십자선·툴팁 대신 캔들마다 `<title>`을 넣어 브라우저 기본 툴팁으로 시·고·저·종을 보여줍니다
- 저가주(96원짜리 인버스 ETF 등)는 하루 변동폭이 1~2원이라 캔들 몸통이 0px이 될 수 있어
  **최소 높이 1px**을 보장합니다. 한 달 내내 가격이 같으면 축 계산에서 0으로 나누므로 그것도 막았습니다

**한 주당 매수/매도 가격** — 실시간 호가는 KRX OPEN API에 없고, 있더라도 이 사이트는 런타임에
외부 네트워크를 타지 않으므로 며칠 전 호가를 커밋해두는 꼴이 됩니다. 그래서 호가 대신
**"한 주 살 때 나가는 돈 / 팔 때 들어오는 돈"**을 계산합니다. 두 값이 달라지는 이유인
**매도할 때만 붙는 증권거래세**가 초보자가 가장 자주 놓치는 지점이기도 합니다.

| 구분 | 매수 | 매도 |
|---|---|---|
| 코스피 | 0% | 0.20% (증권거래세 0.05% + 농어촌특별세 0.15%) |
| 코스닥 | 0% | 0.20% (증권거래세 0.20%, 농특세 없음) |
| ETF·ETN | 0% | 0% (증권거래세 면제) |

- **2026년 1월 1일 개정 세율**입니다. 세법이 바뀌면
  [`src/data/domestic/index.ts`](./src/data/domestic/index.ts)의 `SELL_TAX_RATE` 한 곳만 고치면 됩니다
- 위탁수수료는 증권사·이벤트마다 달라 **대표 숫자를 지어내지 않았습니다.** 본문 숫자는 법으로
  정해진 세율만 쓰고, 수수료는 "보통 0.015% 안팎이며 증권사마다 다름"이라고 주석으로만 밝힙니다

**수집기 변경** — 기존에 버리던 일별 시·고·저·종가를 `daily.json`으로 남깁니다.
KRX는 하루치 전 종목이 한 응답에 담기고 이미 그 응답을 전부 훑고 있어서,
**추가 네트워크 요청은 0건**입니다.

### 국내 주식 — 매수·매도 판단 도우미 (기술적 신호)

"이 종목을 지금 사도 되는지 팔아야 하는지 가늠할 재료"를 종목 상세 페이지에 붙였습니다.
화면 구성은 인베스팅닷컴·트레이딩뷰의 **기술적 요약**(적극매수/매수/중립/매도/적극매도)을
따랐고, 지표는 토스증권이 초보자에게 권하는 기본 3종(이동평균선·MACD·RSI)을 축으로 골랐습니다.
여기서 익힌 이름이 실제 증권사 앱에서 그대로 통하게 하려는 의도입니다.

**먼저 데이터를 6개월로 늘렸습니다.** 기존 1개월(21영업일)로는 20일선이 마지막 하루치만
나오고 60일선·MACD·RSI는 아예 계산되지 않습니다. 지표를 넣으려면 과거가 필요해서, 위에
적은 2단계 수집으로 바꿨습니다.

**점수에 넣는 신호 다섯 개** — 성격이 겹치지 않게 추세 3 + 오실레이터 2로 골랐습니다.
비슷한 지표를 여러 개 넣으면 같은 신호를 중복해서 세어 한쪽으로 쏠립니다.

| 신호 | 매수 쪽 | 매도 쪽 |
|---|---|---|
| 주가 vs 20일선 | 종가가 위 | 종가가 아래 |
| 20일선 vs 60일선 | 정배열 | 역배열 |
| 5일선 vs 20일선 | 골든크로스 상태 | 데드크로스 상태 |
| RSI(14) | 30 이하 (과매도) | 70 이상 (과매수) |
| MACD(12·26·9) | MACD선이 시그널선 위 | 아래 |

- 두 선이 사실상 붙어 있는데 소수점 차이로 방향을 단정하지 않도록 **±0.5% 무시 구간**을
  두고, 그 안쪽은 중립으로 셉니다
- 종합은 단순 합계가 아니라 **계산된 지표 수로 나눈 비율**을 씁니다. 상장 직후라 60일선이
  없는 종목은 지표가 넷뿐인데, 그때 합계 −2를 다섯 개짜리와 같은 잣대로 재면 실제보다
  약하게 나오기 때문입니다. 계산 가능한 지표가 3개 미만이면 아예 판정하지 않습니다
- 거래량(평소의 몇 배)·6개월 가격대에서의 위치·하루 평균 등락폭은 **점수에 넣지 않고**
  참고 수치로만 보여줍니다. 방향을 가리키는 값이 아니기 때문입니다

**"사세요/파세요"라고 쓰지 않는 것은 의도한 원칙입니다.** 이 계산에는 회사의 실적도 뉴스도
들어 있지 않아 그렇게 말할 근거가 없고, 그런 표현은 투자 권유가 됩니다. 모든 문구를
*"신호가 어느 쪽으로 기울어 있다"*까지만 말하도록 맞췄고, 판정 카드 바로 아래에 한계를
명시한 뒤 **사기 전 스스로 답해볼 질문 5개**(무엇으로 돈을 버는 회사인지, 전 재산의 몇 %인지,
손절 기준을 정했는지 등)를 붙였습니다. 초보자에게 실제로 필요한 것은 결론보다 이쪽입니다.

- 계산은 전부 [`src/data/domestic/signals.ts`](./src/data/domestic/signals.ts)의 순수 함수이며
  **빌드 타임에 한 번** 돌고 HTML로 굳습니다. 브라우저 자바스크립트는 여전히 0줄입니다
- 순위표(`/domestic`)에도 종합 결과를 배지 한 칸으로 붙여, 어떤 종목을 열어볼지 고를 수 있게 했습니다
- 차트의 가격 축은 이제 **이동평균선까지 포함**해 잡습니다. 급락한 종목은 20일 평균이 이번 달
  가격대 밖에 있어 선이 화면 위로 잘려 나가던 문제가 있었습니다

### 국내 주식 — 기업 가치 지표와 판단의 틀

기술적 신호만으로는 판단의 한쪽 다리가 비어 있습니다. **“값이 너무 비싸졌을 때”는 파는
이유가 되는데, 그 판단은 차트로는 절대 할 수 없기 때문**입니다. 그래서 종목 상세 페이지를
세 갈래로 채웠습니다.

| 섹션 | 무엇을 보나 | 자료 출처 |
|---|---|---|
| 지금 분위기는 어느 쪽일까 | 가격이 어떻게 움직였나 (지표 5종) | KRX 시세 |
| 이 회사는 얼마짜리인가 | 값어치가 얼마인가 (시총·PER·PBR) | KRX + DART |
| 캔들 하나 읽는 법 | 그날 무슨 힘겨루기가 있었나 | KRX 시세 |
| 그래서, 사야 할까 팔아야 할까 | 사람이 지켜야 할 규칙 | — |

**시가총액·상장주식수·순자산가치는 추가 요청 0건으로 얻었습니다.** KRX 일별매매정보 응답에
`MKTCAP`·`LIST_SHRS`가 이미 들어 있었고, ETF는 `NAV`(순자산가치), ETN은
`PER1SECU_INDIC_VAL`(증권당 지표가치)까지 같은 응답에 있습니다. 시가총액은 종가 × 주식수를
우리가 직접 곱하지 않고 거래소 계산값을 그대로 씁니다. 우선주·자기주식 처리에서 어긋나기
때문입니다.

**ETF·ETN에는 PER·PBR이 없습니다.** 회사가 아니라 여러 종목을 담은 그릇이라 재무제표 자체가
없습니다. 대신 담긴 것의 값어치와 시장 가격을 견주는 **괴리율**이 정확히 같은 자리를
대신합니다. 사실 초보자에게는 이쪽이 더 직접적입니다 — 만 원짜리를 만 오백 원에 사는지가
바로 보이기 때문입니다.

**숫자에 좋다·나쁘다 색을 칠하지 않은 것은 의도한 설계입니다.** 초보자가 가장 흔히 하는
착각이 “PER 10이면 싸고 25면 비싸다”인데, 비교 기준 없는 배수는 아무 뜻이 없습니다.
평소 30배에 거래되던 회사의 25배는 싼 것이고, 평소 8배이던 회사의 10배는 비싼 것입니다.
그래서 값은 계산하되 판정하지 않고, **무엇과 비교해야 하는지**를 문장으로 붙였습니다.
DART 주요계정 응답이 당기·전기·전전기 3개년을 한 번에 주므로, 추가 요청 없이
**3년 순이익 흐름**(늘고 있나 줄고 있나)까지 함께 보여줍니다. PER 한 숫자보다 이쪽이
중요하기 때문입니다.

**캔들 읽는 법** — 캔들을 그려놓고 “빨강은 오른 날”만 알려주면 절반만 설명한 것입니다.
캔들 하나가 담은 정보는 방향이 아니라 **몸통과 꼬리의 비율**에 들어 있는 그날의 힘겨루기입니다.

- 구조도와 대표 모양 6종을 **인라인 SVG로 직접** 그립니다 (외부 이미지 0건, JS 0줄)
- 기준일 캔들이 장대양봉·도지·망치형 중 무엇인지 [`candles.ts`](./src/data/domestic/candles.ts)가
  **자동 판독**합니다. 같은 모양이라도 어디서 나왔는지에 따라 이름이 달라지므로(하락 끝의
  망치형 ↔ 상승 끝의 교수형) 직전 5영업일 흐름을 함께 봅니다
- **캔들 색과 등락률이 어긋나는 문제**를 명시적으로 설명합니다. 색은 *그날 시가* 대비이고
  등락률은 *전날 종가* 대비라, 전날보다 낮게 출발해 조금 회복하면 빨간 캔들인데 전일 대비는
  마이너스가 됩니다. 수집한 시세 2,152일 중 **400일(18.6%)** 이 그런 날이었습니다.
  흔한 혼동이라 실제 종목별 횟수를 세어 함께 보여줍니다

**사고파는 판단의 틀** — 신호만 보여주고 끝내면 “빨간불이면 사고 파란불이면 판다”는 잘못된
습관을 오히려 심어주게 됩니다. 그래서 팔아야 하는 세 가지 이유(산 이유가 사라졌을 때 /
값이 너무 비싸졌을 때 / 더 좋은 곳이 생겼을 때)와 **파는 이유가 아닌 네 가지**(주가가
떨어져서 / 한 분기 실적이 나빠서 / 나쁜 뉴스가 나와서 / 많이 올라서)를 나란히 놓고,
매도 기준은 **사기 전에** 정하라는 세 질문으로 닫습니다.
